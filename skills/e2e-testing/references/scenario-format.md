# 시나리오 파일 형식

## 구조

```markdown
# 시나리오 {번호}: {기능명}

## 사전조건
- {필요한 로그인 역할, 사전 데이터 등}

## 테스트

### {번호}.1 {테스트명}
- **type**: auto
- **액션**: {수행할 행동을 자연어로 구체적으로}
- **기대**: {기대하는 결과}

### {번호}.2 {테스트명}
- **type**: human
- **액션**: {에이전트가 준비할 행동}
- **유저 행동**: {유저가 직접 해야 할 것}
- **기대**: {유저 행동 완료 후 기대하는 결과}
```

## 작성 규칙

- 파일명: `{번호}-{기능명}.md` (예: `2-students.md`)
- 1개 파일 = 1개 기능 영역 = 1개 에이전트가 실행
- 테스트 번호: `{시나리오번호}.{테스트번호}` (예: 2.1, 2.2)
- 모든 스텝에 `type` 필드 필수 (`auto` 또는 `human`)
- **액션**: agent-browser가 수행 가능하게 구체적으로 (페이지 경로, 클릭 대상, 입력 값)
- **기대**: snapshot/screenshot으로 확인 가능한 UI 상태
- 사전조건에 로그인 필요하면 `credentials.md`의 어떤 계정 사용할지 명시
- 테스트 데이터는 테스트 내에서 생성 → 테스트 끝에서 정리 (CRUD 순서)
- `human` 스텝은 가능한 시나리오 후반부에 배치

## human이 필요한 경우

- 실제 PG 결제 (카드 입력, 본인 인증)
- CAPTCHA / reCAPTCHA
- OTP / 2FA 인증
- 외부 서비스 콜백 확인 (알림톡 수신 등)
- 실물 기기 조작 (바코드 스캔, 프린터 출력 등)
